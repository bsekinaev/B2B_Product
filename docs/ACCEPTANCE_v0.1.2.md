# Приёмка v0.1.2 — B2B Product Content Generator

**Дата проверки:** 5 ноября 2026 года.  
**Ветка:** `feat/b2b-v012-quality-foundation`.  
**Исходный коммит перед подготовкой релиза:** `b61a763`.  
**Статус:** кандидат на релиз; итоговый тег и merge в `main` ещё не выполнены.

## Что проверил

После исправления ограничения параллелизма выполнил локально 369 тестов (PASS), branch coverage 96,24%, Ruff, pip check и офлайн-приёмку HTTP API. В GitHub Actions прошли все четыре проверки на Ubuntu и Windows. Это результаты коммита `b61a763`; после изменений для выпуска версии 0.1.2 контрольный прогон повторяется.

Оформил 20 исходных товаров и обработал их через реальный GigaChat. Получил 20 из 20 карточек со статусом `ready_for_review`: SEO-описания выдержали длину 800–1200 символов, характеристики не изменились, обязательные поля заполнены. Одна ранняя попытка ОВЕН 2ТРМ0 была неуспешной, её заменил отдельный разрешённый retry без удаления старого результата.

Формальная проверка не оценивает смысловую точность всех технических утверждений. Для 2 из 20 итоговых SEO-текстов зафиксировано совпадение с модельным ответом; для остальных 18 — несовпадение. Этот показатель не позволяет однозначно установить число случаев fallback. Сохранённые live-результаты не перезаписываю: они нужны для воспроизведения проверки.

## Десять одновременных запросов

| Режим | HTTP 200 | HTTP 429 | Итог |
|---|---:|---:|---|
| Подменённая модель, 10 потоков | 10 | 0 | Конкурентная обработка API работает |
| GigaChat `GIGACHAT_API_PERS`, 10 потоков | 1 | 9 | Ограничение провайдера |

После этого добавил семафор: один активный запрос к GigaChat на процесс, остальные ожидают свободный слот (до 120 секунд). При превышении времени ожидания приложение возвращает HTTP 429. Ограничитель не координирует несколько процессов и не заменяет внешнюю очередь. Дополнительных реальных запросов к GigaChat после исправления не делал.

## Редакторские замечания

Проверка JSON выявила повторяющиеся обороты в резервном SEO-описании. Кроме того, в одной реальной карточке ОВЕН ТРМ1 обозначения вариантов выходных устройств названы режимами; такой текст нельзя публиковать без исправления. Для новых генераций переработал распределение параметров по разделам: погрешности и время опроса отнесены к измерительным характеристикам, размеры и исполнение — к монтажным, электрические и остальные свойства — к отдельной группе. Исторические live-результаты при этом не изменены.

Статус `ready_for_review` остаётся техническим статусом черновика, а не редакторским разрешением на публикацию. Для изделий-серий нужно отдельно подтвердить характеристики выбранной модификации по документации производителя.

## Как проверить

```powershell
.\.venv\Scripts\python.exe -m pip install --no-deps --no-build-isolation -e .
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m ruff format --check .
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m pytest -q --cov=app --cov-branch --cov-fail-under=95
.\.venv\Scripts\python.exe -m scripts.run_acceptance
```

Офлайн-команды не используют ключи GigaChat. Установка editable-пакета без зависимостей обновляет метаданные версии для OpenAPI. Редакторскую оценку полученных текстов эти тесты не заменяют.

## Что не входит в этот релиз

Не реализованы авторизация внешних клиентов, распределённый rate limiter для нескольких worker-процессов, фоновая очередь и автоматическая публикация карточек. Приложение предназначено для локального запуска и проверки.
