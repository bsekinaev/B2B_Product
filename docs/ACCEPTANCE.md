# Приёмка MVP — B2B Product Content Generator

Дата проверки: **3 ноября 2026 г.** Версия: **0.1.0**, кандидат к выпуску.
Основа — тестовое задание «AI-помощник для подготовки товарных описаний».
Это фиксация известных результатов, а не акт полной SEO-приёмки.

## Соответствие заданию

| Требование | Реализация / результат |
|---|---|
| Входной JSON товара | `POST /generate`, Pydantic `ProductInput` |
| Генерация через LLM API | GigaChat Python SDK, TLS, коды ошибок |
| Удобный структурированный ответ | JSON: `GenerationResult` |
| SEO-заголовок до 70 символов | Проверяется валидатором |
| SEO-описание 800–1200 символов | Проверяется, **в live-примерах не достигнуто** |
| Структурированные характеристики | Копируются без изменений из входа |
| 3–5 поисковых запросов | Проверяются количество и уникальность |
| Коммерческий блок | Генерируется; неполный ответ помечается |
| Недостаточные данные | `insufficient_data`, `missing_fields`, `warnings` |
| Некорректный JSON / ошибки API | Контролируемый отказ, без разглашения секрета |
| Примеры двух товаров | Два иллюстративных входа, скрипт экспорта live-результатов |
| README / промпты / ограничения | README и исходники `app/llm/prompts.py` |

**Ограничение исходного ТЗ:** в предоставленном PDF приведён подробный JSON
одного манометра; второго полного паспортного набора нет. Используемый
демонстрационный термометр не является подтверждённой карточкой реального изделия.

## Риски, которые остаются

1. **SEO-длина (существенное отклонение).** Данные примеров недостаточно
   подробны для гарантированного содержательного описания на 800–1200 символов.
   Нужны факты из паспортов, не новые приёмы искусственного удлинения.
2. **Смысловая достоверность.** Фильтр подозрительных чисел и терминов
   эвристический. Проверять назначения, совместимость, ГОСТ, поверку,
   условия поставки и гарантию должен контент-менеджер.
3. **Модель и воспроизводимость.** У разных версий модели и квот GigaChat
   длина и формулировки ответа могут различаться. Примеры результата —
   снимки отдельного запуска, не обещание идентичного текста.
4. **Публичное API.** `/generate` не содержит аутентификации. Допустим
   локальный прототип; внешний доступ без отдельного security review запрещён.
5. **Повторы / время ожидания.** До двух редакторских генераций плюс
   внутренние повторы SDK; строгий end-to-end дедлайн операции не реализован.
6. **Секреты / данные.** `.env`, локальные сертификаты и `artifacts/` исключены
   из Git. Экспортированные примеры в `examples/results/` предназначены для
   ручной проверки перед публикацией исходного кода.

## Приёмка перед сдачей

Запустить из чистой Python 3.12 среды команды README; проверить `/health`,
выполнить офлайн-приёмку, затем при наличии доступа — live-приёмку.
Для примеров результата выполнить `scripts.export_live_examples --confirm-live`
и **просмотреть полные JSON** перед добавлением в Git. После этого проверить
`git diff --cached --check`, список staged-файлов и отсутствие настоящих
ключей и закрытых сведений. Не выдавать `ready_for_review` за готовность к
публикации, а незавершённую SEO-часть — за выполненную.
