# Техническое задание — B2B Product Content Generator

**Этап:** v0.1.2 — качество и надёжность (исторический документ)
**Основа:** v0.1.1, коммит 2c51135
**Язык документации:** русский
**Статус:** архивный план версии v0.1.2; требования этой версии уже реализованы.
**Актуальная техническая приёмка:** [v0.1.3](ACCEPTANCE_v0.1.3.md). Этот документ не является новым ТЗ для версии 0.1.3.

## 1. Назначение

Разработать надёжный сервис формирования черновиков
B2B-карточек контрольно-измерительных приборов.

Система принимает структурированные сведения о товаре,
использует GigaChat для генерации текста, выполняет независимую
проверку результата и возвращает JSON с диагностикой.

Технические характеристики принадлежат исходным данным.
Языковая модель не вправе изменять их.

Статус ready_for_review означает необходимость проверки
редактором, а не разрешение на публикацию.

## 2. Цель версии v0.1.2

Устранить обнаруженные технические недостатки v0.1.1:

- восстановить автоматическое тестирование;
- согласовать версии приложения и документации;
- улучшить обработку ошибок конфигурации;
- исключить ненужные LLM-вызовы;
- исправить извлечение отрицательных формулировок;
- повысить точность проверки характеристик;
- разделить проверку HTTP и качества генерации.

Сохранить обратную совместимость JSON API.

## 3. Исходное состояние

В версии v0.1.1 реализованы:

- Python 3.12, FastAPI, Pydantic, GigaChat SDK;
- POST /generate и GET /health;
- SEO-заголовок, SEO-описание, поисковые запросы;
- коммерческий блок;
- детерминированный fallback;
- проверка неподтверждённых утверждений;
- сохранение исходных характеристик;
- 280 тестов, покрытие ветвлений 96%;
- 24 синтетических сценария;
- два примера товарных карточек.

Демонстрационные результаты использовали офлайн-fallback.
Успешная live-генерация текущей версии не доказана
этими результатами.

## 4. Функциональные требования

### REL-01 — CI/CD

При каждом push в рабочую ветку и pull request:

1. Установить Python 3.12 и зависимости.
2. Выполнить pip check.
3. Выполнить Ruff lint и format check.
4. Запустить pytest с branch coverage не ниже 95%.
5. Проверить HTTP API без доступа к GigaChat.
6. Проверить 24 синтетических сценария.

Матрица: Ubuntu и Windows.

CI не требует реальных токенов GigaChat.
Ошибка любой проверки блокирует успешное завершение job.

### REL-02 — Версионирование

Версия в OpenAPI должна совпадать с версией Python-пакета.

Запрещено поддерживать две независимые константы версии.
Добавить тест согласованности метаданных пакета и API.

Версию 0.1.2 установить перед финальным релизом.

### DOC-01 — Документация

README должен отражать фактическое состояние проекта.
Исправить устаревшие заявления о непубликации v0.1.1.

В документации различать:

- тесты с подменённым провайдером;
- воспроизведение записанных ответов GigaChat;
- реальные обращения к GigaChat;
- редакторскую проверку.

Не утверждать успешное промышленное внедрение без доказательств.

### API-01 — Ошибки конфигурации

Ошибки GIGACHAT_SCOPE, GIGACHAT_BASE_URL,
GIGACHAT_VERIFY_SSL_CERTS и других настроек
должны обрабатываться безопасно.

Ожидаемый HTTP-ответ:

- код 503;
- detail.code = configuration;
- без ключей, токенов и traceback.

GET /health продолжает работать без реквизитов GigaChat.

### GEN-01 — Недостаточные характеристики

Если в specs нет ни одного заполненного значения:

- не обращаться к языковой модели;
- вернуть status = insufficient_data;
- указать недостаток характеристик;
- сохранить исходный specs без изменения.

Наличие description не отменяет это правило.

### GEN-02 — Проверка отрицаний

Запрещено превращать отрицательные утверждения
в положительные.

Примеры:

- «Не предназначен для измерения давления».
- «Не для измерения давления».
- «Не используется для измерения давления».
- «Применение для измерения давления не подтверждено».

Если назначение не подтверждено, его нельзя заявлять
как свойство товара.

Сохранить корректную обработку положительных примеров.

### VAL-01 — Привязка характеристик

Не считать число подтверждённым только потому,
что оно встречается где-нибудь во входном JSON.

Для поддерживаемых сценариев сопоставлять:

- диапазон измерений и значение;
- диаметр и значение;
- класс точности и значение;
- резьбу и её обозначение.

Пример ошибки: исходный диаметр 100 мм не подтверждает
заявление о диапазоне измерения 100 МПа.

Не допускать ложных отклонений существующих примеров.

### QA-01 — Live Quality Gate

Разделить два независимых результата:

HTTP_CONTRACT:
корректность HTTP-ответа, структуры и сериализации.

CONTENT_QUALITY:
достижение требований к содержанию и статусу генерации.

HTTP 200 с requires_revision не считается успешной
редакторской приёмкой.

Строгий live-режим должен возвращать ненулевой exit code,
если качество хотя бы одного результата не соответствует
условиям.

Live-запуск выполняется только по явному флагу.

### SEC-01 — Защитные требования

Сохранить:

- обязательную проверку TLS;
- официальный адрес GigaChat;
- ограничения размера HTTP-тела;
- запрет дублирующихся JSON-ключей;
- запрет передачи секретов в ответах;
- контроль неподтверждённых утверждений;
- отсутствие автоматической публикации.

## 5. Обратная совместимость

Сохранить маршруты:

- GET /health
- POST /generate
- GET /docs

Вход:

- name
- manufacturer
- specs
- description

Выход:

- status
- card
- missing_fields
- warnings

card содержит:

- seo_title
- seo_description
- specifications
- search_queries
- commercial_note

Не менять структуру ответа без отдельного решения.

## 6. Нефункциональные требования

Python 3.12.
Чистая установка на Windows и Ubuntu.
Покрытие ветвлений не ниже 95%.
Тесты без реальных сетевых обращений по умолчанию.

Синхронный GigaChat SDK не должен блокировать event loop.

Не добавлять новые зависимости без обоснования.
Не изменять опубликованный тег v0.1.1.

## 9. Ограничения

Регулярные выражения не заменяют полноценный фактчекинг.

Недостаточные исходные данные не позволяют всегда
получать SEO-описание длиной 800–1200 символов.

Варианты серии не являются готовым исполнением изделия.

Офлайн-тесты не подтверждают качество каждого будущего
ответа реального GigaChat.

Публичный доступ к API без аутентификации и квот
не входит в v0.1.2.
