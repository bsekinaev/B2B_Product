# Аудит проекта перед v0.2.0 — контрольная точка

**Дата:** 8 ноября 2026 года.  
**Проверенный `main`:** `8c6f61a8a596cd0b428998481947f84c5b48e4b3`.  
**Опубликованный релиз:** `v0.1.3` (не изменяется).  
**Цель:** установить точное состояние и повторно использовать уже реализованные решения, не выдавая дорожную карту за готовые функции.

## Реально реализовано

| Область | Подтверждённые файлы и поведение | Решение для v0.2.0 |
|---|---|---|
| HTTP API | `app/main.py`: `GET /health`, `POST /generate`, OpenAPI; локальный сервис | Не менять существующий JSON-контракт |
| Входные товары | `app/schemas.py`: `ProductInput` с `name`, `manufacturer`, `specs`, `description` | Переиспользовать модель, расширение каталога — отдельно |
| Генерация и защита фактов | `app/generator.py`, `app/validation.py`, `app/editorial_claims.py`, `app/seo_completion.py` | Повторно использовать, не переписывать |
| Трассировка | `GenerationMeta`: маршрут SEO, логические LLM-вызовы, коды причин | Дополнить связью с записью каталога и ревизией в следующих инкрементах |
| Пакетный диагностический сценарий | `scripts/run_live_batch.py`, `examples/live_batch/manifest.json`: идентификаторы, `input_sha256`, `catalog_reference`, `source_scope`, защита от повтора записи | Использовать как образец импорта, но не считать рабочей очередью |
| Проверки | 723 локальных теста, 95,45% покрытия ветвлений; CI Windows/Ubuntu PASS для v0.1.3 | Не снижать защитные критерии |
| Документация | `docs/ARCHITECTURE_PLAN.md` описывает v0.2.0–v0.5.0 | Использовать как согласованную архитектурную основу |

## Ещё НЕ реализовано

- Постоянный каталог с идентичностью товара, серии и конкретного исполнения.
- PostgreSQL, SQLAlchemy, Alembic, таблицы `products`, `product_variants`, `attribute_values`, `sources`, `card_revisions`.
- Привязка конкретного значения характеристики к проверяемому источнику на уровне доменной модели.
- Восстанавливаемые задания и централизованная идемпотентность: текущие JSON-отчёты в `artifacts/` не являются БД или брокером.
- CSV/Excel-импорт, Celery/Redis, редакторский кабинет и роли, ревизии/утверждение, экспорт в CMS.
- Проверенное редакторское качество ≥4/5 после LLM-08 и доказанная бизнес-экономика.

## Найденные заделы

1. Уже описана предметная модель будущей БД: `product_categories`, `attribute_definitions`, `products`, `product_variants`, `attribute_values`, `sources`, `generation_jobs`, `card_revisions`, `claim_evidence`, `review_events`.
2. `source_scope=series|configured_variant`, ссылку на каталог и SHA-256 файла уже содержит диагностический манифест, но они не входят в `ProductInput`.
3. Правила независимой валидации, редакторские статусы и маршрутизация LLM/fallback пригодны для применения к товарам из будущего каталога.
4. Дорожная карта подтверждает модульный монолит: v0.2 — каталог и БД; v0.3 — массовая обработка; v0.4 — редакторский контур; v0.5 — эксплуатация и LLMOps.
5. На момент проверки нет открытых Issues/PR, а старые feature-ветки относятся к v0.1.2/v0.1.3, не к реализованной v0.2.0.

## Архитектурные и продуктовые риски

| Риск | Значимость | Предохранитель |
|---|---|---|
| Ошибка атрибуции характеристики конкретному исполнению | Критическая | Явная принадлежность значения: серии или варианту; ссылки на источник |
| Иллюзия полноценного фактчекинга по наличию чисел | Критическая | Claim evidence с `supported/unsupported/unknown`; ручное решение |
| Устаревшие сведения и потеря исходного значения | Высокая | Неизменяемый исходный снимок, источник и хеш |
| Потеря результатов при перезапуске | Высокая | PostgreSQL, миграции, репозиторий хранения |
| Рост сложности раньше продуктовой проверки | Высокая | Небольшие инкременты; пока без микросервисов и UI |
| Неподтверждённая экономия редактора | Высокая | Размеченная оценка 30 товаров; измерение времени и причин отказов |
| Секреты, небезопасная сеть/URL | Высокая | TLS, без автоматического скачивания внешних ссылок; локальный сервис |

## Заключение

**Статус v0.1.3:** технически завершён и опубликован.  
**Старт новой линии:** v0.2.0, сначала достоверная предметная модель и источники.  
**Порядок:** инварианты и тесты → PostgreSQL/Alembic → сохранение/чтение → импорт проверенных товаров → техническая приёмка.  
**Ограничение:** ни один этап не даёт разрешения на автоматическую публикацию карточек.
