# V013-LLM-01 v2 — карантин коммерческих утверждений модели

## Причина повторной реализации

LLM-01 v1 автоматически превращал результат с неподтверждённой гарантией/сертификатом/преимуществом в `ready_for_review`. Это нарушило 9 ранее действовавших регрессий безопасности. **Ни тесты, ни старый валидатор не ослабляются.**

## Семантика v2

Для карточки с достаточной фактической базой (не менее 8 исходных характеристик), валидным SEO и потенциально опасным непустым коммерческим блоком:

1. Генератор заменяет **только** `commercial_note` на текст, построенный из источника.
2. Результат **обязательно** остаётся `requires_revision`; он не прошёл автоматическую приёмку.
3. `warnings` содержит ошибки исходного ответа с явным префиксом «Исходный коммерческий блок модели».
4. `generation_meta.seo_source=initial_llm`, `reason_codes` содержит `commercial_quarantined`; исходный SEO-черновик сохраняется для работы редактора.
5. Повторная независимая валидация всех полей обязательна. Если она не проходит, карантин не применяется и остаётся существующий путь refinement/fallback.

Этот механизм **не является публикацией, самостоятельным фактчекингом или автоматическим одобрением**. Человек должен рассмотреть первоначальный сигнал и отредактировать черновик. После отдельного одобрения нужен повторный вызов валидатора уже над проверенными данными.

## Что остаётся прежним

- `ready_for_review` в обычной генерации, схема HTTP API и валидатор.
- Все отказы на неподтверждённые гарантии, стандарты, преимущества и новые числа.
- Редакторский повтор короткого SEO, недостаточные исходные данные, повреждённый JSON, rate-limit и ограничения провайдера.
- `specifications` остаётся дословной копией исходных параметров.
- Никаких новых запросов к GigaChat не делается.

## Приёмка

Ожидается: полные Ruff/pytest/coverage/HTTP-acceptance PASS на Windows и в последующем CI; `tests/test_llm01_quarantine_v013.py` PASS, исходные негативные тесты PASS.

Работа выполняется в `feat/v013-editorial-quality`, `main` не меняется. Коммит/push только после полной проверки и отдельной приёмки.
