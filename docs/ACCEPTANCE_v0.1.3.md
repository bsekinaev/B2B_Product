# Приёмка v0.1.3 — B2B Product Content Generator

**Дата:** 7 ноября 2026 года.
**Ветка подготовки:** `feat/v013-editorial-quality`.
**Исходный проверенный коммит:** `b9399773445948f856d57429e1a9bbd16b37f18f`.
**Статус:** техническая приёмка пройдена; итоговая редакторская приёмка не подтверждена. Все карточки требуют ручной проверки до публикации.

## Что реализовано

- SEO-заголовки, описания, поисковые запросы и коммерческие блоки проходят независимую валидацию.
- Структурированные `specifications` копируются из входного товара и не переписываются LLM.
- При неполных/сомнительных ответах применяются ограниченный редакторский повтор, безопасный fallback либо статус `requires_revision`.
- `generation_meta` фиксирует выбранный источник SEO: `initial_llm`, `refined_llm`, `llm_grounded`, `fallback` или `none`, число логических LLM-вызовов и коды причин.
- `llm_grounded` сохраняет исходный модельный SEO и дополняет его только подтверждёнными данными при строго определённых условиях, затем повторно валидирует всю карточку.
- Добавлены предметные защиты от ошибочных технических атрибуций, объединения альтернативных исполнений, подмены обозначений модели, неподтверждённых гарантий, сертификатов и возможностей интерфейсов.

## Реальные вызовы GigaChat

Контрольные тройки товаров: РОСМА БТ-51.211, ОВЕН ТРМ202, ОВЕН ПД200.

| Метрика | LLM-05 (до безопасного дополнения) | LLM-07 (после LLM-06, до LLM-08) |
|---|---:|---:|
| Гибридный `llm_grounded` | 0/3 | 1/3 |
| Полный `fallback` | 3/3 | 2/3 |
| Логических вызовов GigaChat | 6 | 5 |
| Итоговых формальных PASS | 3/3 | 3/3 |
| Изменённых входных характеристик | 0 | 0 |

В LLM-07 модельный текст для ТРМ202 сохранён и дополнен по исходным фактам, но редакторская проверка обнаружила ошибочное написание модели «ТРДМ202» в поисковых запросах и неподтверждённые утверждения о независимом регулировании и удалённом управлении через RS-485.

Патч **LLM-08** добавил регрессионные блокировки этих трёх типов ошибок. Он прошёл офлайн-тесты и CI. **Повторная реальная проверка после LLM-08 не проводилась**, поэтому не заявляется, что все реальные карточки теперь соответствуют редакторскому порогу.

Архивы реальных испытаний хранятся локально в игнорируемом Git каталоге `artifacts/`; они не включаются в релиз и не перезаписываются.

## Критерии и решение

| Критерий | Статус |
|---|---|
| Технический контракт API | PASS |
| Полный pytest / Ruff / зависимости / офлайн HTTP | PASS |
| CI Windows и Ubuntu для LLM-08 | PASS |
| Сохранность исходных `specifications` | PASS в контрольных испытаниях |
| Защитные регрессии LLM-08 | PASS офлайн |
| Подтверждённое редакторское качество **≥4/5** | **НЕ ПОДТВЕРЖДЕНО** |
| Автоматическая публикация без редактора | **НЕ РАЗРЕШЕНА** |

**Решение:** v0.1.3 пригодна к технической демонстрации и ручной проверке карточек, но не должна позиционироваться как автономная система публикации или релиз с доказанной редакторской оценкой ≥4/5.

## Запуск проверки

```powershell
.\.venv\Scripts\python.exe -m pip install --no-deps --no-build-isolation -e .
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m ruff format --check .
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m pytest -q --cov=app --cov-branch --cov-fail-under=95
.\.venv\Scripts\python.exe -m scripts.run_acceptance
```

Офлайн-проверки не вызывают GigaChat. Для реального API необходима действующая конфигурация, проверка TLS обязательна. API предназначено для локального запуска.

## Не входит в объём

Автоматическая публикация, ручное подтверждение редакторского качества самим сервисом, гарантированный фактчекинг всех смысловых утверждений, межпроцессный rate limiter и внешняя авторизация.
