# LLM-06: ограниченное дополнение SEO по подтверждённым данным

## Основание

LLM-05 (коммит a87644b) подтвердил 0/3 сохранённых SEO от GigaChat: для РОСМА 672/690, ТРМ202 778/867, ПД200 674/657 символов в двух вызовах. В первом ответе ТРМ202 единственным замечанием была длина, но последующий полный рерайт привёл к неподтверждённому применению. Для РОСМА обнаружена ещё и семантическая подмена: «гильза длиной 100 мм» вместо исходного «длина погружной части 100 мм». Для ПД200 модель объединяла HART и RS-485 как одну конфигурацию.

## Поведение

1. Если первый ответ модели имеет только одно предупреждение — SEO короче требуемых 800 символов, но длиной не менее 650, — допускается локальное дополнение из заполненных спецификаций.
2. Применимо только к товарам с минимум 8 заполненными характеристиками, исходным описанием и непустым коммерческим блоком.
3. Первая часть SEO остаётся **побуквенно без изменений**. Дополнение выбирает исходные значения характеристик, не создаёт новые технические свойства. Кандидат повторно проходит `validate_generated_card`.
4. При успехе результат получает `seo_source=llm_grounded`, `reason_codes=[seo_grounded_completion]`, `llm_attempts=1` — **не** `initial_llm` и не `fallback`.
5. Любые другие предупреждения, отсутствие данных, неудача повторной валидации сохраняют прежний путь refinement/fallback или карантина. Никакой автоматически одобренной опасной формулировки.
6. Валидатор блокирует конкретное выявленное смешение длины погружной части и длины защитной гильзы, если длина гильзы не представлена отдельной характеристикой.

## Ограничения

`ready_for_review` — статус **только для ручной редакторской проверки**. Гибридный текст может быть стилистически хуже или содержать семантическую ошибку, не обнаруженную детерминированной проверкой. Не автоматическая публикация. `llm_grounded` — новое значение enum; потребителям API, проверяющим значения `seo_source`, нужно обновить обработку. Не изменяются основные поля HTTP-карточки и исходные `specifications`.

## Критерии тестов

- Точный близкий к нормативу реальный текст ТРМ202 — сохранить первоначальное SEO, добавить проверяемую информацию, 800–1200 и ровно 1 вызов.
- Исходное неверное утверждение РОСМА о длине гильзы — блокировать, не дополнять автоматически.
- Неверные альтернативы ПД200, рискованная гарантия — не дополнять.
- Все прежние negative tests, Ruff, coverage >= 95%, офлайн HTTP и CI Windows/Ubuntu должны оставаться PASS.

Старые `artifacts/live_batch/`, `artifacts/llm03_evidence/`, `artifacts/llm05_evidence/` остаются нетронутыми. Новых вызовов GigaChat до установки и тестов не требуется.
