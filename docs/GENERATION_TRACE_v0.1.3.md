# V013-02 — происхождение итогового SEO-текста

В версии 0.1.3 ответ `POST /generate` дополняется полем `generation_meta`.
Структура `status`, `card`, `warnings` и `missing_fields` остаётся прежней.
Для чтения старых сохранённых JSON поле необязательное: отсутствие означает
`generation_meta: null` при разборе через актуальную Pydantic-модель.

## Контракт

```json
{
  "generation_meta": {
    "seo_source": "fallback",
    "llm_attempts": 2,
    "reason_codes": [
      "seo_too_short",
      "refinement_requested",
      "refinement_rejected",
      "fallback_selected"
    ]
  }
}
```

`seo_source` указывает **фактически выбранный** текст:

- `initial_llm` — принят текст первого структурированного ответа модели;
- `refined_llm` — принят текст повторной редакторской генерации;
- `fallback` — итоговое SEO создано локальным алгоритмом по исходным данным;
- `none` — SEO-текст не получен, например из-за недостатка характеристик
  или некорректного JSON при недоступном fallback.

`llm_attempts` — количество логических вызовов `generate_text` приложения.
Учитываются также вызовы, завершившиеся исключением. Сетевые повторы
внутри GigaChat SDK отдельно не подсчитываются. При недостаточных
характеристиках значение равно нулю.

`reason_codes` — упорядоченный перечень решений генератора:

| Код | Значение |
|---|---|
| `insufficient_specs` | Не хватает заполненных характеристик; модель не вызывалась |
| `invalid_llm_json` | Первый ответ не прошёл разбор структурированного JSON |
| `seo_too_short` | Текст первого ответа короче минимального требования |
| `commercial_missing` | Первый ответ не содержит коммерческого блока |
| `refinement_requested` | Сделан второй логический запрос на редакторскую доработку |
| `refinement_failed` | Повторная генерация завершилась ошибкой или некорректным ответом |
| `refinement_rejected` | Повторный ответ не улучшает результат или добавляет предупреждения |
| `refinement_selected` | Повторный ответ выбран для итогового SEO |
| `fallback_unavailable` | Невозможно собрать резервное SEO из исходных данных |
| `fallback_rejected` | Сформированный резервный текст не прошёл формальные проверки |
| `fallback_selected` | Резервный текст выбран в итоговую карточку |

## Что метаданные не доказывают

`seo_source` устанавливается самим генератором при выборе результата,
а не по совпадению строк. Его нельзя достоверно восстановить из старых
20 live-файлов: поле `model_seo_text_retained` фиксирует только сравнение,
а не путь принятия решения. Исторические файлы не изменяются.

Метаданные не подтверждают смысловую достоверность SEO и не заменяют
проверку технических паспортов. Статус `ready_for_review` по-прежнему
означает черновик, который должен проверить редактор.

В метаданных нет токенов, реквизитов GigaChat, промптов, исходных
ответов SDK и трассировки исключений. Ошибки HTTP-провайдера по-прежнему
возвращаются установленными безопасными кодами, без раскрытия деталей.

## Приёмка V013-02

1. Первый валидный ответ → `initial_llm`, один вызов.
2. Принятый редакторский повтор → `refined_llm`, два вызова.
3. Выбран локальный fallback → `fallback`, фактическое число вызовов.
4. Характеристик нет → `none`, ноль вызовов.
5. Некорректный JSON без доступного fallback → `none`, один вызов.
6. Старые результаты без `generation_meta` продолжают разбираться.
7. Полный pytest, branch coverage ≥95%, Ruff и HTTP-приёмка проходят офлайн.

Релиз `v0.1.2` и его исторические результаты остаются неизменными.
