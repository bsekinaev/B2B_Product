# LLM-02B — SEO без механического дубля таблицы, сокращение длинного черновика

## Диагноз

- В историческом аудите: 20 товаров, 21 попытка, 20 формальных PASS, 39 логических LLM-вызовов.
- Для 18 товаров SEO не совпадало дословно с сохранённым ответом модели; происхождение **всех 20** исторических итогов — `unknown`. Это НЕ доказательство 18 fallback.
- Пары исходных характеристик занимают 401–765 символов. Полное дублирование в SEO 800–1200 ограничивает место для связной речи.

## Изменения

1. Системный промпт больше не требует перечислять **каждую** характеристику в SEO. Он рекомендует 3–6 релевантных подтверждённых параметров; все исходные `specifications` сохраняются сервисом отдельно.
2. Для ответа с SEO длиннее 1200 символов и достаточными исходными фактами допускается **один** редакторский повтор на сокращение. В `generation_meta.reason_codes` записывается `seo_too_long`.
3. Сокращённый результат принимается только при `ready_for_review`, без предупреждений или отсутствующих полей. Иначе работает старый fallback/отказ. Суммарно не более двух логических LLM-вызовов.
4. Не меняются JSON-схема ответа модели, HTTP-контракт, валидатор, `commercial_quarantined` из LLM-01 и исторические данные.

## Границы проверки

Офлайн-фикстуры проверяют маршрутизацию и безопасность, **не качество фактического текста GigaChat**. Новые реальные запросы требуют отдельного разрешения владельца и ограниченного бюджета.

## Приёмка

Ruff, pytest с coverage >=95%, offline HTTP, pip check; затем коммит/CI только отдельным шагом. Оценка редакторского качества от этого изменения автоматически не повышается.
