# Генератор B2B-карточек товаров

[![Проверки проекта](https://github.com/bsekinaev/B2B_Product/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/bsekinaev/B2B_Product/actions/workflows/ci.yml)

**B2B Product Content Generator** — HTTP-сервис для подготовки черновиков товарных карточек контрольно-измерительных приборов с использованием GigaChat. Проект создан как тестовое задание на позицию AI/LLM-разработчика в компании «Союз-Прибор». Промышленное внедрение не заявляется.

**Текущая версия: [v0.1.3](https://github.com/bsekinaev/B2B_Product/releases/tag/v0.1.3)** (опубликована 7 ноября 2026 года). Код прошёл техническую приёмку; **тексты требуют ручной редакторской проверки до публикации**.

[Инструкция проверяющему](docs/REVIEWER_GUIDE.md) · [Приёмка v0.1.3](docs/ACCEPTANCE_v0.1.3.md) · [Изменения v0.1.3](docs/RELEASE_NOTES_v0.1.3.md) · [Все документы](docs/README.md)

## Что делает сервис

- Принимает название, производителя, технические характеристики и необязательное исходное описание товара.
- Формирует SEO-заголовок, SEO-описание, 3–5 поисковых запросов и коммерческий блок через GigaChat или безопасный резервный маршрут.
- **Не отдаёт технические характеристики на редактирование модели:** поле `specifications` формируется из исходного `specs` без изменения значений.
- Проверяет структуру результата, длину текста и ряд рискованных утверждений: неправильное обозначение модели, неподтверждённые гарантии, свойства интерфейсов и смешение вариантов исполнения.
- При необходимости делает один редакторский повтор. Для подходящего короткого ответа может сохранить текст модели и дополнить его исходными фактами (`llm_grounded`). При ошибках использует детерминированный `fallback` или возвращает статус доработки.
- Возвращает источник итогового SEO, число логических вызовов модели и причины решений через `generation_meta`.

**Стек:** Python 3.12, FastAPI, Pydantic 2, pydantic-settings, GigaChat SDK, pytest, pytest-cov, Ruff. CI выполняется на Windows и Ubuntu.

## Как формируется карточка

```text
Исходный JSON с характеристиками
              |
              v
Проверка и нормализация входных данных
              |
              v
GigaChat: четыре текстовых поля
              |
              v
Независимая проверка качества и технических утверждений
              |
              +--> принятие черновика модели
              +--> дополнение фактами или один редакторский повтор
              +--> резервная генерация из исходных характеристик
              +--> отказ с объяснением, если безопасный текст не получен
              |
              v
Карточка + статус + предупреждения + generation_meta
```

Исходные характеристики сохраняются независимо от выбранного маршрута. Статус `ready_for_review` означает прохождение формальных проверок и **не является разрешением на автоматическую публикацию**.

## Быстрый запуск

Пример для PowerShell на Windows с установленным Python 3.12:

```powershell
git clone https://github.com/bsekinaev/B2B_Product.git
Set-Location B2B_Product

py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"

Copy-Item .env.example .env
```

Для реальной генерации укажите `GIGACHAT_CREDENTIALS` в `.env` и подходящий `GIGACHAT_SCOPE`. Проверка TLS обязательна; при необходимости доверенный сертификат указывается через `GIGACHAT_CA_BUNDLE_FILE`. **Не добавляйте `.env` и ключи доступа в Git.**

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

После запуска доступны:

| Адрес | Назначение |
|---|---|
| [`/docs`](http://127.0.0.1:8000/docs) | Swagger UI на русском |
| `GET /health` | Проверка сервиса, работает без GigaChat |
| `POST /generate` | Создание черновика, требует настроенного GigaChat |

Сервис предназначен для **локального запуска**, не для открытого публичного API без дополнительной защиты.

## Пример запроса

Используется [JSON термометра РОСМА](examples/submission/products/rosma_bt_51_211.json). Он служит демонстрационным источником, а не подтверждением редакторской пригодности будущего текста.

```powershell
$Json = Get-Content -LiteralPath ".\examples\submission\products\rosma_bt_51_211.json" -Raw -Encoding UTF8
$Body = [System.Text.Encoding]::UTF8.GetBytes($Json)
Invoke-RestMethod -Uri "http://127.0.0.1:8000/generate" -Method Post -ContentType "application/json; charset=utf-8" -Body $Body
```

**Вход:** `name`, `manufacturer`, `specs`, необязательное `description`.

**Выход:** `status`, `card`, `missing_fields`, `warnings`, `generation_meta`. В `card` находятся `seo_title`, `seo_description`, `specifications`, `search_queries` и `commercial_note`.

| Статус | Значение |
|---|---|
| `ready_for_review` | Формальные проверки пройдены; требуется редактор |
| `requires_revision` | Обнаружены нарушения или неподтверждённые утверждения |
| `insufficient_data` | Исходных технических данных недостаточно |

`generation_meta.seo_source` принимает `initial_llm`, `refined_llm`, `llm_grounded`, `fallback` или `none`. Поля `llm_attempts` и `reason_codes` помогают разбирать выбранный маршрут, но не измеряют качество содержания.

Два воспроизводимых примера и сведения об источниках доступны в [`examples/submission/`](examples/submission/) и [`provenance.json`](examples/submission/provenance.json). Они подготовлены через воспроизведение записанных ответов модели и локальную резервную генерацию, **а не как прямые успешные ответы GigaChat**.

## Демо для работодателя без API-ключа

[Проверяемый сценарий генерации карточки: от входного JSON до статуса редакторской проверки](docs/PORTFOLIO_SCENARIO.md). Используются реальные fixtures из репозитория, офлайн-приёмка и пояснение, почему успешная автоматическая проверка **не равна** готовности текста к публикации.

## Проверки и результаты

Офлайн-команды не требуют API-ключа и не расходуют квоту GigaChat:

```powershell
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m ruff format --check .
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m pytest -q --cov=app --cov-branch --cov-fail-under=95
.\.venv\Scripts\python.exe -m scripts.run_acceptance
```

**Подтверждённые результаты v0.1.3:**

| Проверка | Результат |
|---|---|
| Pytest | **723 теста пройдены** |
| Покрытие с ветвлениями | **95,45%** |
| Ruff, зависимости, офлайн HTTP API | Пройдены |
| GitHub Actions | Windows и Ubuntu — пройдены |
| Реальный GigaChat, диагностический прогон LLM-07 | 1 гибридный результат и 2 резервных на 3 товарах |

[Финальный CI версии](https://github.com/bsekinaev/B2B_Product/actions/runs/42405956960) · [Подробная приёмка](docs/ACCEPTANCE_v0.1.3.md)

**Важно:** после заключительных защитных изменений LLM-08 отдельный реальный прогон GigaChat не выполнялся. Редакторский критерий **≥4/5 не подтверждён**; автоматические тесты не заменяют смысловую вычитку.

## Ограничения

- Проверки достоверности основаны на детерминированных правилах и эвристиках: они не заменяют сверку с паспортом производителя и работу технического редактора.
- Для товара-серии характеристики отдельных исполнений нельзя автоматически считать совместимыми. При недостаточных данных корректный SEO-текст длиной 800–1200 символов не гарантируется.
- Семафор ограничивает одновременные обращения к GigaChat **в пределах одного процесса**; распределённой очереди и общего лимитера нет.
- Авторизация внешних клиентов, интеграция с CMS и автоматическая публикация не реализованы.
